## 1. Анализ идеи

### Что мы продаём поиску

Ситуация редкая и потому выигрышная: **на модель Selecline BM1250C в рунете нет нормальной
инструкции с закладкой ингредиентов**. Это подтверждено дважды:

- тема владельца на hlebopechka.ru — «в документации не указаны нормы закладки ингредиентов»;
- базы инструкций (manualslib и аналоги) точной BM1250C не содержат.

При этом **контроллер и панель управления полностью совпадают с Judge JEA43**: те же кнопки
`Time+ / Time− / Loaf size / Menu / Colour / Start-Stop`, те же размеры `1.5 lb / 2.0 lb`
и та же последовательность всех 15 программ, включая редкие `13 Gluten Free`, `14 Knead`,
`15 Yogurt`. Значит, у нас на руках рабочая книга рецептов для этой печки, которой больше
ни у кого в русском интернете нет.

Это и есть контентное преимущество: не «ещё один сайт рецептов для хлебопечки», а
**единственный источник по конкретной модели**.

### Спрос: честная оценка

Запросы низкочастотные — «selecline bm1250c инструкция», «selecline хлебопечка рецепты»,
«861382 bm1333», «хлебопечка ашан инструкция», «bm1250c программы». Суммарно это десятки,
максимум сотни показов в месяц. Зато:

- конкуренции нет почти никакой (выдача забита барахолками Festima и форумными обрывками);
- интент максимально узкий — человек уже держит эту печку в руках;
- вокруг ядра легко нарастить средне-НЧ хвост, который и даст основной трафик:
  «сколько воды на 500 г муки в хлебопечке», «почему в углах ведёрка остаётся сухая мука»,
  «7 г дрожжей это сколько чайных ложек», «колобок в хлебопечке какой должен быть»,
  «программа basic сколько по времени».

Вывод: **идея жизнеспособна**, но целиться надо не в бренд-запрос, а в проблемные
хвостовые запросы, где наш уникальный контент отвечает лучше всех.

### Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Ничтожный трафик по бренду | высокая | тянем хвост: колобок, меры, специи, тайминги программ |
| Медленная индексация github.io | средняя | sitemap.xml + Google Search Console + Яндекс.Вебмастер вручную |
| Претензия по копирайту на текст инструкции Judge/Panasonic | низкая | не выкладываем PDF и не копируем текст дословно: рецептура (список ингредиентов и пропорций) авторским правом не охраняется, всё описание пишем своими словами и ставим ссылку на первоисточник |
| Ответственность «сделал по сайту — не получилось» | средняя | дисклеймер: это не официальная инструкция производителя, а адаптация по OEM-аналогу |
| Google посчитает сайт thin content | средняя | 12+ страниц реального объёма, инфографика, FAQ, разметка Schema.org |
| Домен github.io ранжируется слабее своего | средняя | заложена возможность переезда на свой домен (CNAME) без переписывания ссылок |

## 2. Три варианта реализации (MVP-приоритет)

### Вариант A — статический сайт-генератор на Python + Jinja2 → GitHub Pages ✅ выбран

Данные (рецепты, программы) лежат в JSON, страницы генерируются скриптом в `docs/`,
GitHub Pages раздаёт папку `docs/` напрямую — без CI, без Node, без Jekyll.

- **Плюсы:** полный контроль над HTML и микроразметкой (а это главное для попадания в
  рецептовые блоки Google), нулевая стоимость, добавить рецепт = дописать объект в JSON,
  сайт открывается даже двойным кликом по файлу.
- **Минусы:** свой генератор надо поддерживать самому.
- **Трудозатраты MVP:** 4–6 часов.

### Вариант B — чистый HTML без генератора

Пишем 12 готовых HTML-файлов руками.

- **Плюсы:** ноль зависимостей, максимально просто отдать другому человеку.
- **Минусы:** правка шапки/меню = правка 12 файлов; микроразметку легко разъехаться.
- **Трудозатраты:** 3–4 часа, но каждая последующая правка дороже.

### Вариант C — Jekyll / Hugo / Astro

- **Плюсы:** экосистема тем, GitHub Pages собирает Jekyll сам.
- **Минусы:** ради 12 страниц тащим Ruby/Node, темы генерируют лишний HTML, а тонкую
  настройку JSON-LD всё равно придётся делать руками.
- **Трудозатраты:** 6–10 часов, из них половина — борьба со сборкой.

**Решение: A.** Объём контента маленький и фиксированный, а цена ошибки в разметке высокая —
поэтому важнее контроль над HTML, чем экосистема.

## 3. Стек

- Python 3.12 + Jinja2 — генерация (единственная зависимость).
- Контент: JSON (`data/recipes.json`, `data/machine.json`) + HTML-фрагменты (`data/pages/`).
- Вёрстка: один CSS-файл, CSS-переменные, тёмная тема, ноль JS-фреймворков
  (маленький inline-скрипт только для переключателя темы).
- Инфографика: **inline SVG**, а не картинки — векторно на любом экране, весит копейки,
  текст внутри читается поисковиком, работает в тёмной теме.
- SEO: `<title>`/`description` под каждую страницу, canonical, OG, JSON-LD
  (`Recipe`, `HowTo`, `FAQPage`, `BreadcrumbList`), `sitemap.xml`, `robots.txt`.
- Хостинг: GitHub Pages из папки `docs/` ветки `main`.

## 4. Оценка трудозатрат

| Этап | Часы |
|---|---|
| Генератор, шаблоны, CSS | 3 |
| Перенос и вычитка контента (инструкция, 15 программ, 7 рецептов) | 3 |
| Инфографика (SVG: панель, закладка, колобок, сравнение с Judge) | 3 |
| SEO-обвязка, разметка, sitemap | 1 |
| Публикация, Search Console, Вебмастер | 1 |
| **Итого MVP** | **~11 часов ≈ 1,5 дня** |

Дальше — по 20–30 минут на новый рецепт.

## 5. Что делать после публикации

1. Залить репозиторий, включить Pages (Settings → Pages → Deploy from branch → `main` / `/docs`).
2. Добавить сайт в Google Search Console и Яндекс.Вебмастер, скормить `sitemap.xml`.
3. Оставить ссылку в теме на hlebopechka.ru про BM1250C и в отзыве на otzovik.com —
   это и живой трафик, и сигнал для индексации.
4. Сфотографировать свою печку (панель, ведёрко, готовый хлеб, колобок на 15-й минуте) и
   заменить SVG-заглушки реальными фото: уникальные фото по этой модели усилят страницы.
5. Дописывать хвост по одному запросу в неделю: ржаной, бородинский, тесто для пиццы,
   кулич, безглютеновый, йогурт на программе 15.
